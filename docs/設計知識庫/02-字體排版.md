## 1. 核心法則

1. **字型分類定基調**——揀字之前先諗清楚個 mood：serif 係「傳統／優雅」，sans-serif 係「簡潔／現代」，display 係「搶眼大字」，monospace 係「科技感」，handwriting 係「人性化暖感」；揀錯分類成個設計氣質就錯。
2. **字越大、行高越細**——大字本身已經自帶視覺分隔，行高再拉大反而令每一行「脫節、分離」。
3. **正文行高 1.5 倍係安全起點**——16px 正文配 24px 行高（1.5×），舒服又唔密。
4. **行高過大＝割裂**——標題行高開到 1.5 會破壞「鄰近性原則」（相關嘅嘢要黐埋），睇落成個設計鬆散。
5. **每行 50–60 個字符**——太長讀者會跳行迷路，太短閱讀節奏斷斷續續；呢個係正文黃金行長。
6. **字重用嚟建層級、唔好用嚟冚全場**——標題 600–700、正文 400/medium、強調先局部 bold；成版都 bold 就冇晒衝擊力。
7. **tracking 要「諗過先加」**——大標題可以負 tracking（書示範 -6%）收緊、全大寫／細字加少少 tracking 提升清晰度，但一多啲字母就「脫節」。
8. **字階靠級距唔靠黃金比例**——書作者唔 buy 黃金比例／大三度，直接用「+2px／+4px／+8px」遞增，保證層級「鮮明差異」（80→56→32→20）。
9. **HTML 語意標籤＝層級＋無障礙＋SEO**——H1–H4 唔只係視覺大小，仲係搜尋引擎爬文嘅路標；H1 要放關鍵字但唔好堆砌（keyword stuffing 傷 SEO）。
10. **打破規則前，先學識守規則**——書金句「You can break them, but only after you nail it!!!」；基礎未熟就亂嚟 = 災難。

## 2. 具體數字規格（可直接抄落 CSS）

### 2.1 字階（Typescale）建立法（書作者嘅做法，非黃金比例）

| 步驟 | 規則 | 數字 |
|---|---|---|
| 基準字級 | UI 用 16px；Web 可以更大 | UI `16px`／Web `18px・20px・24px` |
| 細字級距 | 基準附近 +/− `2px`（書話 2px 至關重要；4px 太多、1px 唔夠明顯） | `14 15 16 17 18 19 20` |
| 字級下限 | 唔好細過 | base 16 → 唔低過 `10px`；base 17 → 唔低過 `11px` |
| 標題級距 | 超過 18 一律當標題，用 `+4px` 遞增 | `20 24 28 32` |
| Display 級距 | 超過 32 一律當 display，用 `+8px` 遞增 | `40 48 56 …`（書示範 8/12/16/24 遞增） |
| 完整字階 | 由細到大（書圖表原樣） | `10 12 14 16 18 20 24 28 32 40 48 56` |

### 2.3 行高（Line-height）黃金數字

| 對象 | 字級 | 行高 |
|---|---|---|
| 正文 body | `16–18px` | `1.4–1.6×` |
| body copy 起點（書建議） | — | `1.5×`（再評估） |
| body copy 可變範圍 | — | `1.4–2×`（視內容寬度／長度） |
| 具體例子 | `16px` | `1.5× = 24px` |
| 標題 headings | `32px+` | `1.1–1.2×` |
| display 文字（如標題） | — | `1–1.25×` |

> 邏輯：字越大、行高越細。大字本身自帶分隔，唔使靠行高區分。

### 2.4 行長（Line-length）

| 對象 | 上限 |
|---|---|
| 正文 body text | 每行 `50–60` 個字符（含空格） |
| 標題 headings | 可以更短（標題係醒目，唔係流暢閱讀） |

### 2.5 字重（Weight）

| 用途 | 字重 |
|---|---|
| 標題 Headings | `600–700`（bold / semi-bold） |
| 正文 Body | `400`（regular）或 `500`（medium） |
| 強調／CTA（局部） | `bold` 選擇性用（關鍵詞／CTA） |
| 警示 | 唔好過度——成版 bold 會失去衝擊力 |

書截圖實測字重：
- display 主標 `64px semibold`
- subheading `16px regular+bold`
- body `18px regular`
- CTA `16px medium`
- body-data `18px semibold`

### 2.6 字距（Tracking / Letter-spacing）

| 場景 | 數字 |
|---|---|
| 負 tracking 示範（書對比） | 左 `0%`（❌）→ 右 body `-2%`、heading `-6%`（✔） |
| SF PRO 例子 | tracking `-6%` 就變成「SF PRO Display」效果（p268） |
| 大寫／小字號 | 加少少 tracking 提升清晰度（書：全大寫文字、較小字號） |
| kerning | 網頁**唔使手動改**——優質字體設計師已預設好字距微調 |

> 書**冇**俾 0.25em 呢個數，只有 −2%／−6% 呢兩個負 tracking 示範值；大標要唔要 0.25em 要按字體性格自己實測（見 HIRYU checklist）。

| 元素 | Desktop | Tablet | Mobile |
|---|---|---|---|
| H1 | `80px` | `64px` | `44px` |
| H2 | `56px` | `56px` | `32px` |

### 2.9 字型分類 × 例子 × 用途（含 font pairing 方向）

| 分類 | 例子（書列名） | 最啱用喺 |
|---|---|---|
| Serif 襯線 | Louize、Reckless Neue | 標題、傳達傳統／優雅；article/blog |
| Sans-serif 無襯線 | Helvetica、Arial、Inter、Montserrat、Roboto、Poppins | 科技／新創／UI-UX；body + 標題 |
| Display 展示 | Lobster、Bebas Neue、Abril Fatface、Impact | Logo、hero、headline、banner（**少用**，過度用會 overwhelming） |
| Monospace 等寬 | Courier New、Consolas、Source Code Pro、IBM Plex Mono、Roboto Mono、JetBrains Mono | code block、terminal、科技感產品 |
| Handwriting 手寫 | Pacifico、Dancing Script、Brush Script、Great Vibes、Caveat | 創意、invitation、branding、accent／logo（**唔好用嚟做 body**） |

**Font pairing 方向（書有提但冇硬性組合表）：**
- 「喺網頁設計可以揀 1 種字型淨係用嚟做標題、另一種用嚟做正文」（p270）
- 隱含配法 = **標題 serif + 正文 sans**（serif 啱標題傳優雅，sans 啱正文清晰易讀）
- 同族對比示範：DM Sans ↔ DM Serif Display（同一家族一對襯線／無襯線）
- 揀字型要檢查：可讀性、可縮放性（小 caption → 大標題都要靚）、字重數量（至少要有 light/regular/bold 三級，正文字體必須夠）
- 唔知揀咩字 → 直接揀 **Inter**（免費、高 x-height、專為螢幕設計、Google Fonts + Figma 內建；官網會俾你字級→tracking/行高自動公式）

## 3. 常見錯誤（書入面嘅負例）

1. **正文行高開 1**——密到黐埋，難讀（書對比圖：行高 1 ❌ vs 1.5 ✔）。
2. **標題行高開 1.5**——太大，各行文字互相「分離」、破壞鄰近性（書對比圖：heading 行高 1.5 ❌ vs 1.1 ✔）。
3. **字級層級唔夠鮮明**——H2/H3/H4 之間冇「鮮明差異」，讀者分唔到邊個重要（書要求 56→32→20 咁遞減）。
4. **行長太長**——讀者跳行、迷失位置；**行長太短**——閱讀斷斷續續（書話 50–60 字符先啱）。
5. **tracking 加太多**——字母睇落「互相脫節」（書：只要剛好夠清晰，唔好多過頭）。
6. **成版 bold**——「too much bold text loses its impact」，強調變咗冇強調。
7. **handwriting 攞嚟做 body**——長段落難讀（書：只做 accent／logo／decorative heading）。
8. **display 字體過度使用**——大字搶眼但「can feel overwhelming if overused」，只留 hero／headline。
9. **字級細過下限**——低過 10px（base 16）／11px（base 17）會難讀。
10. **H1 堆砌關鍵字**——keyword stuffing 傷 SEO（書：H1 放關鍵字係好，但過度堆砌有反效果）。
11. **字級／行高一奇一偶**——書 pro tip：文字大小用偶數，行高都跟偶數（對比：37px 總高 ❌ vs 40px ✔，行高 21px ❌ vs 24px ✔）。

## 4. 落地 HIRYU checklist（心喬 Summer · mood 藍紫版）

> HIRYU 現狀（真源 `hiryu/docs/品牌憲章-v3-暗夜花海.md`）：拉丁 display 用 Cormorant Garamond Light 300 Italic（幽玄新藝術）；中文 display 用源樣明體／思源宋體 Light；正文 UI 用 Geist／Inter Tight；楷書詩句用霞鶩文楷；主標 96–128px、正文 16px。

**即改／即核實：**

1. **主標行高要 1.1–1.2×**：HIRYU 主標 96–128px 已遠超書嘅 32px+ 標題線，行高跟書規格應該係 `1.1–1.2`（display 甚至可以 `1–1.25`）。⚠️ 核實：而家 hero 標題 line-height 係咪開咗太大（例如 1.3–1.5）搞到「脫節」？要收返窄。
2. **正文字級 16px → 行高鎖 24px**：書明示 16px × 1.5 = 24px。核實 HIRYU 正文 Geist／Inter Tight 嘅 line-height 係咪啱啱 24px（150%），唔好淨係跟 default。
3. **每行 50–60 字符**：核實 HIRYU 正文 column 嘅 `max-width`，令每行中文字大概 50–60 個字（唔好一行拖到 80+ 字先換行）。
4. **字級層級有冇「斷崖」**：HIRYU 主標 96–128px 對正文 16px 差成 6–8 倍，中間有冇 H2/H3（例如 56／32／20）去填補？書嘅層級係 80→56→32→20 咁「鮮明遞減」，如果 HIRYU 淨係得「超大標 + 16px 正文」兩級，會冇中層節奏。
5. **Light 300 做 display 係咪太單薄**：書嘅 display 主標係 `64px semibold`、標題字重建議 `600–700`。Cormorant Garamond Light 300 Italic 係走幽玄優雅，屬 serif display 例外，但 300 喺 96–128px 大尺寸會唔會「冇咗衝擊力」？核實：大標係咪要上返 Cormorant 中等字重（或靠負 tracking 收緊），定 Light 加 letter-spacing 已經夠。
6. **tracking 方向要反轉嚟諗**：書嘅負 tracking（-2%／-6%）係針對粗體 sans 大標；HIRYU 用 Light 300 Italic 全大寫／中文大字，書另一條 rule 係「全大寫／細字加 tracking 提升清晰度」。⚠️ 書**冇 0.25em 呢個數**——所以「大標 tracking 0.25em」要自己開 Inspector 對住個字逐級試（0.05／0.1／0.15em），睇邊個唔散、唔黐。唔好盲抄 0.25em。
7. **楷書（霞鶩文楷）只做 accent**：書 handwriting rule「唔好用嚟做 body、只做 accent／詩句點綴」。核實 HIRYU 楷書只係詩句級，冇攞嚟砌長段落。
8. **中文 display 字重對比度**：黑曜石 `#10100F` 底 + 藍紫光軸，思源宋體 Light 喺暗底會唔會太幼、唔夠對比？書強調「字重用嚟建層級 + 引導視線」，核實中文大字喺 mood 藍紫版底上夠唔夠實（考慮 Light → Medium）。
9. **響應式縮字級唔縮層級**：書 H1 80→64→44。HIRYU 主標 96–128px 喺 mobile 要跟比例縮（對照書約縮到 44–56px），唔好硬 keep 96px 塞爆手機；body 縮到 16px。核實 breakpoint 字階有冇寫死。
10. **全部字級／行高用偶數**：書 pro tip（偶數 rule）。核實 HIRYU 字級、行高冇 17px／21px 呢啲奇數殘留（書負例正正係行高 21px ❌ → 24px ✔）。
11. **小字唔好低過 10–11px**：核實 HIRYU 嘅 caption／footer／fine print 冇細過 10px（中文仲要保守啲，建議 12px 起）。
12. **font pairing 方向已啱，但要核對同一行混排**：HIRYU「Cormorant（拉丁）＋思源宋體（中文）」display + 「Geist／Inter Tight」正文，正正係書嘅「標題 serif + 正文 sans」。⚠️ 要核實中英混排喺同一標題行時，兩隻 display 字嘅 x-height／字重比例會唔會失衡（中文宋體 Light vs Cormorant Light 300 要視覺對齊）。

## 5. 原文金句

1. 「The larger the text, the smaller the line height should be. Big text is easier to read, so you don't need extra spacing to distinguish one line from another.」（字越大、行高越細；大字易讀，唔使靠行高分開行。）
2. 「The optimal line length for your body text is considered to be 50 to 60 characters in a line.」（正文最佳行長＝每行 50–60 個字符。）
3. 「Don't overdo it—too much bold text loses its impact.」（唔好過度——太多粗體會失去衝擊力。）
4. 「You can break them, but only after you nail it!!! Only AFTER YOU NAIL BASICS.」（你可以打破規則，但前提係你先熟透基本嘢！）
5. 「過大的行高會使標題產生割裂感，破壞了鄰近性原則——即彼此相關的項目應該靠得更近。」
6. 「As a general rule for display text (like headings), aim for a line-height of 1–1.25x.」（display 文字一般行高 1–1.25×。）
