## 1. 核心法則

1. **60-30-10 配色比例**——60% 主導色（多數係背景）、30% 次要色（字體／圖標／視覺元素）、10% 強調色（CTA／核心圖標／緊急通知）；比例啱，畫面先自動平衡、有節奏。
2. **七種配色方案係和諧嘅骨架**——互補、分裂互補、單色、類似、三角、四角（雙互補）呢啲「規劃過嘅色彩組合」幫你攞視覺平衡；唔使靠估。
3. **互補色專責搶眼**——直接跨過色輪攞對面隻色（紅↔綠、藍↔橙），對比最強，啱用嚟引視線去關鍵位；分裂互補係佢嘅柔和版。
4. **多色 mix 要「同飽和度、同明度」先和諧**——書用 Superlist 做示範：一堆唔同色相（藍紫粉綠）但飽和度明度一致，先做得出成熟高級嘅調色盤。
5. **四角（雙互補）一定要揀一個主導色**——唔係就亂成馬戲團；用色越多越要有一隻「大佬」壓場。
6. **分層級用色，唔好一嚟就七彩**——第 1 層黑白 → 第 2 層黑白＋一個品牌色 → 第 3 層先多色組合；層級循序漸進，設計先企得穩。
7. **色輪規則係工具唔係鐵律**——書明言「Think of these color rules more as tools rather than absolutes」，最終要靠自己隻眼同品味微調到「啱 feel」。
8. **漸變要用類似色／單色，唔好用互補雙色硬溝**——兩隻互補色直接溝漸變「幾乎一定醜」；想自然無縫，中間要插一隻過渡色。
9. **色彩心理學係起點，唔係規則手冊**——品牌成日為咗市場定位／美學／文化差異而「打破」顏色嘅典型聯想（Spotify 綠、Snapchat 黃、可樂紅），心理學只係「揀色嘅起點」。
10. **對比度要夠，但 WCAG 唔係教條**——文案同 CTA 對比度要守 WCAG 2，但書用「白字 vs 黑字」實例話你知：肉眼感受有時同計算結果相反，要用嚟引導、唔好盲從。

## 2. 具體數字規格（可直接抄落 CSS）

### 2.1 色相環關係（互補／三角／四角／類似）

> ⚠️ 書只係用「幾何描述」講位置（跨過去對面／均勻分佈成三角形／兩組互補對），**冇俾任何度數**。下面「標準度數」一欄係色相環常識，唔係書原文，我列埋俾你對照但唔好當書有寫。

| 方案 | 書嘅描述（原文意思） | 標準度數（書冇寫） |
|---|---|---|
| 互補 Complementary | 「直接跨過色輪搵對面」 | 相距 **180°** |
| 分裂互補 Split-complementary | 「用互補色兩側緊鄰嘅兩隻色」 | 基礎色 ±**150°**（對面兩側各偏 30°） |
| 類似 Analogous | 「色輪上彼此相鄰嘅三隻色」 | 相鄰，間距約 **30°** |
| 三角 Triadic | 「均勻分佈三隻色，形成完美三角形」 | 各相距 **120°** |
| 四角／雙互補 Tetradic | 「兩組互補色對，用晒四隻色」 | 四點，間距 **90°**（矩形） |
| 單色 Monochromatic | 「固定單一色相，玩淺深版」 | 同 hue，只變 S/L |

> 註：書 p212 話「共有七種」，但內文實際描述咗 6 種（上表）。第 7 種應該係「Square 正方形配色」——喺 p234 嘅 Figma 色輪工具選單有列出（Complementary／Split／Monochromatic／Analogous／Triadic／**Square**）。

### 2.2 60-30-10 法則（p241）

| 比例 | 角色 | 書嘅定義 | 用喺邊 |
|---|---|---|---|
| **60%** | 主導色 Dominant | 覆蓋設計大部分區域，通常係背景色（白／灰／黑／米色） | 背景 |
| **30%** | 次要色 Secondary | 襯托主導色 | 字體排版、圖標、視覺元素（淺色主題下係黑／灰；深色主題相反） |
| **10%** | 強調色 Accent | 真正搶眼跳脫嘅品牌代表色，少量節制用 | CTA 按鈕、核心圖標、緊急通知 |

> 書範例 ctrl.xyz：60% 白底 + 30% 黑字 + 10% 亮綠 CTA。書仲話呢個比例「並非一成不變」，只要乾淨俐落、有效引導視線，強調色可以多啲用（例如卡片背景），但主 CTA 一定要保持最突出。

### 2.3 WCAG 對比度門檻（p247 原表）

| 對象 | 最低比例 AA | 增強比例 AAA |
|---|---|---|
| 正文文字 Body text | **4.5:1** | **7:1** |
| 大字體文字 Large text | **3:1** | **4.5:1** |
| 組件／圖示／圖表 Components, icons, graphs | **3:1** | （空白） |

- **大字體定義**：大於 **14px 粗體**，或 **18px 常規體**。
- **唔使全部 4.5:1**：組件（按鈕邊框、圖示、圖表）**3:1 就夠**。
- **白色文字有 100% 亮度、冇色相冇飽和度** → 係「構成對比嘅最強形式」；當高亮度 vs 高亮度比較時，WCAG 計出嚟反而低（書實測：白字明明易讀，但對比度只計到 2.64 唔合格）。
- **禁用元件**對比度低、可能過唔到 WCAG 係「冇問題」——因為用戶根本唔使操作佢。

**書入面嘅實測對比度數值：**

| 情境 | 對比度 | 結果 |
|---|---|---|
| 對比度檢查器示例（文字 `#831843` on 填色 `#FCE7F3`） | `4.99` | AA 通過 |
| 藍色按鈕「下一步 Next」 | `4.26` | AA 通過（但 AAA 唔過） |
| 白字按鈕（較易讀但計算上） | `2.64` | AA / AAA 都唔過 ❌ |
| 黑字按鈕（較難讀但計算上） | `4.5` | AA + AAA 通過 ✅ |
| 大字體差例 | `WCAG 2.92` | AA / AAA 唔過 ❌ |
| 大字體好例 | `WCAG 5.1` | AA 過、AAA 唔過 |
| 次要按鈕（正常可用） | `WCAG 7.2` | AA 通過 ✅ |
| 禁用按鈕（Disabled） | `WCAG 2.29` | AA 唔過（但書話 OK，因為禁用） |

### 2.5 漸變規格（p237 / p243–245）

- **做平滑自然漸變**：用**類似色（analogous）**或**單色（monochromatic）**。
- **再進階**：微調 **飽和度（saturation）／色相（hue）／明度（lightness）**，令漸變更豐富或更自然。
- **負例鐵律**：只用**兩隻互補色**溝漸變「幾乎一定難看」——過渡生硬、唔平滑、冇現代感。
- **解法**：喺兩隻色中間加一隻**過渡色（middle color）**，銜接兩邊色調，漸變先自然無縫。

### 2.6 手動調色（tint／shade／灰階）

**基準色示例（Tailwind 藍，p255–256）：** HEX `#356BF8`｜HSL `223, 93, 59`

| 方向 | 操作 | 明度 Lightness 變化 |
|---|---|---|
| 變淺 Tint | 明度 **+10** | L 59 → `69 / 79 / 89 / 95` |
| 變深 Shade | 明度 **−10** | L 59 → `49 / 39 / 29 / 19` |

> 色相（H 223）同飽和度（S 93）喺純明度調整時保持不變。

**兩條 Pro Tip：**

1. **偏離基準色（亮度 ~50%）時，提高飽和度**——因為喺 HSL 空間，太淺／太深嘅色調會「褪色／沖淡（washed out）」，除非微調飽和度。微小調整、巨大差異。
2. **微調色相**：加色相 = 顏色顯得更淺更亮；減色相 = 更深更暗。可以令色更「rich」而唔「dull」。⚠️ 反方向改（淺色端減 hue、深色端加 hue）書標咗 ❌。

**色票實測值（p257）：**

- 第一組（純明度，S 固定 50）：`S:50 L:90 / 70 / 50 / 30 / 10`
- 第二組（深端加飽和度）：`S:70 L:90 → S:70 L:70 → S:50 L:50 → S:60 L:30 → S:90 L:10`
- Note：如果主色本身已經高飽和度（書例子 93%），就可能**唔使再加大**，但可以試。
- 色相微調組（H 基準 51）：上排 `H:51 L:90/70/50/30/20` → 下排（淺端加 hue、深端減 hue）`H:55 L:90 → H:53 L:70 → H:51 L:50 → H:45 L:30 → H:40 L:20`；反方向組 `H:42/47/51/56/57` 標 ❌。

**灰階調色盤（p258，S 用 8–20、L 由 8 遞增到 98）：**

| 深 → 中 | 中 → 淺 |
|---|---|
| `S:20 L:8` | `S:10 L:60` |
| `S:15 L:18` | `S:12 L:70` |
| `S:12 L:28` | `S:14 L:80` |
| `S:11 L:38` | `S:16 L:90` |
| `S:8 L:50` | `S:20 L:98` |

> 要點：明度逐步 +10，**接近 50% 明度時逐步降低飽和度**（S 由 20 → 8），先做到平衡灰階。

### 2.8 網頁色彩系統 token 規格（p259–262）

**命名規範：**
- ❌ 唔好 hardcode hex（例如 `#EC4899`）；✅ 用語意命名。
- 字面命名：`red-50` … `red-900`（做全域調色盤參考用）。
- 語意命名：`foreground`／`background`／`border`／`accent`；書作者自己用 `fg-primary`／`fg-secondary`，其中「fg」「primary」叫修飾符（modifiers）。

| `fg-secondary` | 600 | `#52525C` | 次要內容，冇咁搶眼但仍要過無障礙（通常 500/600） |

## 3. 常見錯誤（書入面嘅負例）

1. **「全部突出 = 全部唔突出」**（Everything stands out, so nothing stands out）——深色底上面所有文字／元素都白色，開頭乾淨，最後笨重、壓迫、冇嘢抓得住視線。
2. **次要元素對比度太高**——應該只有主要內容最突出，次要文字／元素要降到更柔和、對比度更低嘅色調（灰／柔和色）。
3. **深色主題上白色背景太搶**——任何白色背景喺深色主題都會因強烈對比自動搶走視線，打亂視覺流暢度；應該用「比主深色背景稍淺一啲」嘅微妙背景色。
4. **背景 vs 前景對比度唔夠**——文字／按鈕／圖示同背景對比不足，用戶睇唔清；深色主題冇必要把背景調到比實際需要更淺。
5. **色彩過載 Color overdose**——強調色太多，奪走主 CTA 嘅焦點；「顏色應該幫重要元素突出」，主 CTA 一定要比視覺裝飾更突出。
6. **四角配色冇主導色**——四隻色平均用會亂成馬戲團；必須讓一隻色做主角。
7. **兩隻互補色直接溝漸變**——過渡生硬、唔平滑、顯外行；中間要加過渡色。
8. **飽和度全開、明度亂嚟嘅多色 mix**——唔同色相但飽和度明度唔一致，做唔出 Superlist 嗰種成熟感。
9. **調色盤太臃腫**——書明言網頁設計「唔需要幾十種 tint/shade 嘅龐大調色盤」，簡化做乾淨基礎盤先啱。
10. **hardcode 色碼**——直接寫死 `#EC4899` 呢啲數值難維護、難溝通；要用語意 token。
11. **盲從 WCAG**——書用「白字（肉眼易讀）但 WCAG 計出 2.64 唔合格」vs「黑字（肉眼難讀）但 4.5 合格」做對照，證明唔好教條式跟足。

## 4. 落地 HIRYU checklist（心喬 Summer · mood 藍紫版 · 暗夜花海）

> HIRYU 現有配色 token（真源 `hiryu/docs/品牌憲章-v3-暗夜花海.md`）：
> 玄青黑 `#080B10`（主背景）｜紫晶 `#845EC2`（主色大面積）｜琉璃青藍 `#00B4D8`（焦散）｜緋紅 `#FF2A4D`（極少點綴）｜琉璃骨白 `#F7F4EA`（正文）｜新藝術金絲 `#E2C076`（點睛）。

**即改／即核實：**

1. **60-30-10 比例先對一次**：書嘅骨架係「60% 背景 = 玄青黑 ✓、30% 次要 = 紫晶＋青藍、10% 強調 = 緋紅＋金絲」。⚠️ 要核實：紫晶「大面積」有冇過咗 30% 條線？緋紅＋金絲加埋係咪真係壓到 ≤10%（書強調 accent 要「少量節制」）？如果紫晶面積 >30% 而緋紅都唔係「極少」，成個比例會失衡。

2. **紫晶大面積 vs 書嘅「主色=CTA、背景=中性」原則**：書嘅做法係**飽和色做主導做 CTA，背景用中性（白/灰/黑/米）**。HIRYU 用中飽和嘅紫晶 `#845EC2` 做大面積主色（粗算 HSL ≈ `263°, 45%, 56%`）——唔算全開，但同書「大面積應該俾中性背景」有出入。⚠️ 核實：紫晶大面積係咪要「降飽和／加 dark 變體」先唔會壓過內容？書明確話「深色主題次要區塊用『比主背景稍淺一啲』嘅微妙色」，唔係直接上一隻飽和紫。

3. **多色和諧 = 同飽和度同明度（書 Superlist 鐵律）**：HIRYU 6 隻色嘅飽和度／明度散得好開——青藍 `#00B4D8`（粗算 HSL `190°, 100%, 42%`）同緋紅 `#FF2A4D`（`350°, 100%, 58%`）係**飽和度 100% 全開**，紫晶得 45%、金絲 65%、骨白接近 0%。⚠️ 書 p257 明言「主色已高飽和度（93%）就可能唔使再加」。要核實：青藍＋緋紅兩隻全開，會唔會互相搶、同紫晶「唔同飽和度明度」而唔和諧？可能要統一佢哋嘅 S/L 級距（例如把青藍飽和度拉落同紫晶一檔）。

4. **對比度逐對核實（粗算，要喺 contrast checker 覆核）**：

   | 組合 | 粗算對比度 | 書嘅門檻 |
   |---|---|---|
   | 骨白 `#F7F4EA` on 玄青黑 `#080B10` | ~17.9:1 ✅ | 過 AAA 7:1 |
   | 青藍 `#00B4D8` on 玄青黑 | ~8.0:1 ✅ | 過 AA 4.5 |
   | 緋紅 `#FF2A4D` on 玄青黑 | ~5.3:1 ✅ | 過 AA 4.5 |
   | 金絲 `#E2C076` on 玄青黑 | ~11.3:1 ✅ | 過 AAA |
   | 紫晶 `#845EC2` on 玄青黑 | ~4.1:1 ⚠️ | **略低過正文 AA 4.5**（大標 3:1 先 OK） |
   | 骨白 on 紫晶 | ~4.4:1 ⚠️ | **邊緣唔過正文 AA** |
   | 骨白 on 青藍 | ~2.2:1 ❌ | 唔合格（連大標 3:1 都唔過） |
   | 骨白 on 緋紅 | ~3.4:1 ❌ | 唔過正文，只啱大字 3:1 |
   | 金絲 on 紫晶 | ~2.8:1 ❌ | 唔合格 |

   ⚠️ 重點：**紫晶做大面積時，上面嘅骨白正文（~4.4:1）同「紫晶字 on 玄青黑（~4.1:1）」都唔穩過書嘅 4.5:1 門檻**。書強調「文案同 CTA 係最要過無障礙嘅嘢」→ 建議紫晶要準備 dark 變體（`brand-strong` 700/800）先夠對比，或者紫晶只用喺圖像／裝飾、文字一律放骨白。

5. **文字層級唔好得一個骨白**：書負例「Everything stands out, so nothing stands out」。HIRYU 而家正文＝骨白，但次要文字／caption／說明係咪都係骨白？⚠️ 要加一個 **`fg-secondary`（灰調，書示範 `#52525C` 嗰類）**，令次要內容降對比度，建視覺層級。骨白只留俾主要文字。

6. **緋紅用途收緊做「真·10% accent」**：書講 accent 只係 CTA／核心圖標／緊急通知。核實緋紅 `#FF2A4D` 有冇俾任何「裝飾性」用咗（例如花海閃光、hover 效果），有就收返，否則會變「色彩過載」、搶走主 CTA。

7. **漸變：紫晶→青藍「焦散」要加中間過渡色**：書明言「兩隻色直接溝漸變幾乎一定醜，要加中間色」。HIRYU 紫晶（hue ~263°）同青藍（hue ~190°）相距約 73°，唔係互補（180°）亦唔係緊鄰類似色，做焦散／漸變時 ⚠️ 核實過渡有冇「生硬 band」；書建議用類似色／單色先做到平滑，或中間插一隻過渡色。

8. **補 Tailwind 色階，唔好得單一 hex**：書講每個品牌色要 `strong(700/800) / main(500/600) / subtle(50/100)` 三檔。HIRYU 紫晶、青藍、緋紅、金絲而家各得一隻 hex。⚠️ 即刻補 shades（尤其紫晶要 dark 變體救對比度），金絲要 subtle 變體做 hover 背景。

9. **命名轉語意 token**：書講唔好 hardcode hex，用 `bg-base`／`fg-primary`／`border-subtle`／`brand-strong`。HIRYU 而家 token 名叫「玄青黑／紫晶／琉璃青藍」係詩意名，好記但難做 CSS variable。⚠️ 建議映射：`玄青黑 → bg-base`、`骨白 → fg-primary`、`紫晶 → brand-main`、`青藍 → accent-cyan`、`緋紅 → accent-danger`、`金絲 → accent-gold`，詩意名留做註釋，代碼用語意 token。

10. **禁用／次要狀態對比度**：書話禁用元件對比度低係 OK（用戶唔操作）。但 HIRYU 金絲／緋紅做按鈕時，⚠️ 核實 disabled／secondary 狀態有冇故意降對比（書示範 7.2 ✅ vs 2.29 禁用），唔好所有按鈕都一樣搶。

11. **黑底多冷色係咪夠和諧**：書嘅「同飽和度同明度多色」做法，Superlist 都係深藍底＋一堆近似 S/L 嘅 accent。HIRYU 玄青黑底 + 紫/青藍/緋紅/金 4 隻 accent，方向啱，但 S/L 太散（見第 3 條）→ 書結論「微調、實驗、直到 feel 啱」，建議喺 Figma 色輪（`figma.com/color-wheel/`）開個 square scheme 對住試。

## 5. 原文金句

1. 「Everything stands out, so nothing stands out.」（當所有東西都很突出時，就等於沒有東西是突出的。）
2. 「Being a designer isn't about sticking rigidly to a set of rules—it's about developing a good eye for what works and knowing when to break the "rules."」（做設計唔係死守一套規則，而係練出辨別「咩先 work」嘅眼力，同埋知幾時打破規則。）
3. 「Think of these color rules more as tools rather than absolutes.」（把呢啲色彩規則當成工具，而唔係絕對真理。）
4. 「Color psychology is nice in theory, but how does it really play out in the wild?」（色彩心理學理論上很美好，但現實世界到底點運作？）
5. 「Tweak those colors, experiment, and refine until it feels right. You've got to trust your own eye and taste.」（微調啲顏色、不斷實驗、打磨，直到感覺啱為止——你必須信自己隻眼同品味。）
6. 「When you choose to blend only two complementing colors from the color wheel, the gradient will almost always look bad.」（當你只溝色相環上兩隻互補色，漸變幾乎一定難看。）
