# 03 · 網格排版（Grid & Layout）

> 來源：Web Design Mastery 網格排版章（p296–322）

> 拍檔提一句：p296–320 係「網格與排版」章正文；p321–322 已經係下一章「Visuals（視覺設計）」開頭（書印頁 323–324）。我淨係食咗網格排版章（p296–320）做正文，但 p322 嗰三句排版負例（Bad line-height／Poor Spacing／fine but boring）同排版直接相關，照收落「常見錯誤」。⚠️ 書入面呢章**冇提黃金比例（1.618）**，只有 margin 遞減數值同 1200px 有效排版區，唔好亂估。

## 1. 核心法則

1. **12 欄網格（12-column grid）係最常見嘅網格佈局**——大部分內容型／企業型版面都用佢做對齊基準，想「穩陣」先諗 12 欄。
2. **網格歸結為兩個基本數值：外邊距（margin）+ 欄間距（gutter）**——書金句級原句，兩個數「一致性」先係最重要，其餘都係次要。
3. **垂直節奏靠「行高 = 基線網格嘅整數倍」**——唔同字級嘅 line-height 一定要跟 baseline grid 增量遞增（例如 8px 增量 → 16/24/32/40/48px），文字先會跨欄、跨頁對齊。
4. **由兩個關鍵尺寸開始設計：桌面 1440px、手機 375px**——唔好一嚟就為每個尺寸開稿，先鎖兩頭。
5. **1200px 係「關鍵斷點」**——1440px 稿、兩側各留 120px margin，有效排版區 = 1200px（1440−120×2）；低過 1200px 就開始收版。
6. **margin 隨螢幕縮細而遞減**——桌面 120px → 平板 80/56/48px → 手機 20/16px，係書作者全章反覆用嘅一套數字。
7. **三種響應式行為，按內容揀：固定／流動／混合**——固定＝內容不動、淨係兩側 margin 變；流動＝margin 不動、欄按比例縮放；混合＝full-bleed 元素（header／footer／背景圖）拉到全屏、其餘內容固定。
8. **網格類型揀啱先唔會做錯功**——文字重內容用單欄（Block）、多內容用多欄／模組（Multicolumn/Modular）、圖片卡用瀑布流（Masonry）、「按重要性自由擺位」用階層式（Hierarchical）、特色展示用便當盒（Bento）。
9. **用 auto-layout（flex/grid）可以完全取代正式網格**——書作者自己喺無代碼工具就係咁做，效果一樣、響應式仲易，重點係「一致性 + 適應性」，唔好為咗架構而架構。
10. **視覺縮放技巧：平板 scale、手機重排**——書 trick：視覺區喺平板用 `scale(0.8)` 縮、手機改垂直重排，唔使重新畫一套。

### 2.3 邊距（Margin / Padding）—— 全章最反覆嗰套數

| 裝置 | Margin（書用語 padding 同義，見 p317 註） |
|---|---|
| 桌面 Desktop | `120px`（兩側各留） |
| 平板 Tablet | `80px`／`56px`／`48px` |
| 手機 Mobile | `20px`／`16px` |

- 有效排版區公式（p312）：`1440 − 120×2 = 1200px`（桌面稿）
- 固定網格：margin 隨螢幕增大而**遞增**，內容固定（p313–314）
- 流動網格：margin **固定 80px**，欄按比例縮放（p315）

### 2.4 Framer 屬性面板實值（p317，作者實際排版三稿）

| 裝置 | Gap（間距） | Padding（內邊距） |
|---|---|---|
| Desktop | `80` | `120` |
| Tablet | `32` | 上 `120`／右 `48`／下 `120`／左 `48` |
| Mobile | `32` | 上 `64`／右 `20`／下 `64`／左 `20` |

### 2.5 垂直節奏（Vertical rhythm / Baseline grid）

| 例子 | 基線網格 | 字級／行高 | 出處 |
|---|---|---|---|
| 例 A | `20px` baseline | 標題 `32px` / 行高 `40px`；內文 `14px` / 行高 `20px` | p308 |
| 例 B | `24px` baseline | 標題 `40px` / 行高 `48px`；內文 `16px` / 行高 `24px` | p309 |
| 增量原則 | `8px` 增量 | 行高 = 8 嘅倍數：`16 / 24 / 32 …` | p308 |

> 鐵律：**行高必須係 baseline grid 間距嘅整數倍**，否則文字唔會座正基線，垂直節奏散晒。

### 2.8 網格類型 × 適用場景（p299–307）

| 類型 | 英文 | 一句講清／適用 |
|---|---|---|
| 單欄／手稿 | Block (Manuscript / Single-Column) | 文字重內容：blog、newsletter、文章、About Us、CTA |
| 多欄 | Multicolumn | 兩欄或以上 + 一致 gutter；組織大量圖文、建立內容層級 |
| 模組化 | Modular | 同時分欄 + 分列 → 內容「模組」；大量分類項目展示 |
| 瀑布流 | Masonry | 項目高度唔同、垂直對齊欄；作品集／圖庫／Pinterest |
| 階層式 | Hierarchical | 按重要性／關係自由擺位、歡迎唔同高闊形狀；動態 |
| 便當盒 | Bento | 模組化變體、模組尺寸可變；2024/2025 趨勢 |
| 基線 | Baseline | 垂直節奏網格，隱形但保證行距／排版一致 |
| 行為 | Fluid / Fixed / Hybrid | 流動／固定／混合；另有 Soft / Hard（書冇詳解） |

> ⚠️ 數據出入註記：p316 示意圖左上角寫住 `20px Margins`，但同 p315 流動網格規格面板嘅 `80px` margin 矛盾——估計係 OCR 誤讀（20px 可能係「縮放 80%」或另一標註）。**以 p315 面板 `80px` 為準**，20px 嗰個唔好盲抄。

## 3. 常見錯誤（書入面嘅負例）

> 坦白講：呢章主力係教原則，唔似字體排版章咁有成串「❌ vs ✔」對比圖。書入面**明確**嘅負例得以下幾條（最後三條係下一章 Visuals 開頭但同排版直接掛鈎）：

1. **固定網格喺超大螢幕 → 兩側留白尷過寬**（p314）——內容固定唔郁，螢幕越闊 margin 越肥，睇落「尷尷哋」地空；解法＝針對目標受眾最常用解析度設計，或用流動網格。
2. **針對每一種螢幕尺寸去設計 = 不切實際**（p310）——手機尺寸太多，逐個 cover 係死路；書作者只做標準斷點 + 兩個起始尺寸（1440/375）。
3. **行高不佳（Bad line-height）**（p322）——行高冇跟 baseline 節奏／開得唔啱，文字密到黐埋或散到脫節。
4. **間距不良（Poor Spacing）**（p322）——margin／gutter 唔一致、冇呼吸空間。
5. **「還可以，但好悶」（fine, but boring）**（p322）——版面冇視覺元素／冇層級，文字一大塊；書明講「除非好文案，否則冇人會讀一整塊枯燥文字」。

> 反推負例（書強調「一致性最重要」嘅反面）：margin／gutter 每頁唔同、冇固定網格對齊基準——呢個係書反覆警告但冇畫成負例圖，HIRYU 自查時照樣要當係病。

## 4. 落地 HIRYU checklist（心喬 Summer · mood 藍紫版）

> HIRYU 現有構圖方向：C-curve 包圍場域、無邊界花海、實體留白（上方 40–50% 墨色虛空 vs 下方繁複光影嘅「極簡 vs 極繁」張力）、日式雜誌佈局、導航／標語分散四角。

**即改／即核實：**

1. **Grid 類型應該揀「階層式（Hierarchical）」而唔係死 12-column**：HIRYU「日式雜誌佈局 + 四角分散導航 + C-curve 包圍」本質就係書嘅 hierarchical grid（按重要性自由擺位、歡迎唔同高闊形狀、唔使 uniform 高度）。⚠️ 核實：而家係咪仲係「死中軸 12-column 堆疊」（正正係之前 reference-first 診斷嘅「死中軸堆疊」病）→ 轉 hierarchical 自由擺位，先造到「體量差」。
2. **要個不可見對齊基準嘅話，用 12 欄 + gutter 20px + 有效區 1200px**：書兩張規格面板都係 `12 欄 / gutter 20px`。HIRYU 若保留 12-column baseline 做對齊，直接抄 `grid-template-columns: repeat(12, 1fr); column-gap: 20px; max-width: 1200px; margin-inline: auto;`（桌面 margin 120px）。
3. **Margin 遞減跟書：120 → 80/56/48 → 20/16**：核實 HIRYU 每頁 margin 有冇一致；「四角分散導航」尤其要 check 四角元素離邊距離係咪同一套數，唔好呢頁 120、嗰頁 96。
4. **斷點鎖 1200 / 768，起手 1440 + 375**：核實 HIRYU breakpoint 有冇「1200px 關鍵斷點」；花海背景動畫重嘅頁面，書建議可學 Index.app 用**單一 1200 斷點**簡化（≥1200 桌面版／<1200 手機版），減低動畫 + 斷點相乘嘅複雜度。
5. **「極簡 vs 極繁」張力 → 用 hybrid grid**：書 p316 hybrid 正正講「full-bleed 元素（背景圖）stretch 到全屏、其餘內容 fixed 喺定死區域」。HIRYU 對照：**無邊界花海 = full-bleed stretch**、**文字／商品內容 = fixed 喺 1200px 內**。核實：花海係咪真係 edge-to-edge（冇被 content column 限死），而內容又係咪乖乖固定喺 1200px。
6. **上方 40–50% 墨色虛空要落 baseline 節奏**：書冇「40–50%」呢個數（係 HIRYU 自己嘅方向），亦冇黃金比例。但可以對齊做「vertical rhythm」——令上方虛空高度 = margin／行高嘅**整數倍**（例如 8px 或 24px 增量），先唔會尷尷哋地「半格」。核實：虛空高度係咪跟 baseline 增量，定係亂數。
7. **垂直節奏揀 8px 增量，行高做倍數**：書示範 8px → `16/24/32/40/48`。HIRYU 中文正文（思源宋體 16px）line-height 至少要係 8 嘅倍數（`24px` = 1.5× 啱；標題行高 `40px` = 8×5）。核實：而家行高有冇亂數（例如 1.4 → 22.4px 唔係整數）。
8. **中文行高要 re-verify（唔好照搬英文值）**：書 baseline 例子係英文（14/20、16/24）。中文（思源宋體）通常要 1.6–1.8em 先夠疏。核實：16px 正文行高若用 `24px`（1.5）對中文可能略密，試 `26–29px` 但**都要係 baseline 倍數**（8px 增量下 24 或 32 之間要取捨，或改 4px 增量）。
9. **長文欄限 `max-width: 600px`**：書 auto-layout 例子「Content max width = 600px」。HIRYU 宣言／詩句／商品敘述等長文，閱讀欄限 ~600px（對照 02 章「每行 50–60 字」）。核實：長文有冇限寬，定係拉滿 1200px 搞到一行 80+ 字。
10. **四角分散導航喺手機要「收納」**：書講 mobile 導航收埋喺 menu icon。核實：HIRYU <768px 時，四角分散嘅導航／標語有冇 reflow 方案（收 menu icon／垂直重排），唔好四角元素互相碰撞。
11. **商品卡／C-curve 花海喺平板用 `scale(0.8)`、手機垂直重排**：書 trick 正正啱 HIRYU 呢類視覺重嘅區塊——平板縮 80% 唔使重畫，手機先重排。核實：有冇寫死尺寸而唔識縮。
12. **用 Tailwind flex/grid = 已經係 auto-layout，唔使自建 grid framework**：書明講「用 auto-layout 可完全跳過正式網格、效果一樣、響應式仲易」。HIRYU 用 Tailwind 4，直接 flex/grid utility 就夠，唔好過度工程。

## 5. 原文金句

1. 「When working with type at different sizes, line-height have to be incremental with the baseline grid.」（處理唔同字級時，行高必須跟基線網格嘅增量成倍數遞增。— p308）
2. 「A breakpoint in responsive design is simply the point at which your website's content adapts to offer the best user experience.」（響應式設計嘅斷點，就係你網站內容為咗俾最佳體驗而開始適應嘅嗰一點。— p309）
3. 「When I design, I start with a main screen size of 1440px. However, I account for margins — let's say 120px on each side — leaving an effective layout area of 1200px (1440-120*2).」（我由 1440px 開始設計，兩側各留 120px margin，剩返 1200px 有效排版區。— p312）
4. 「Hybrid grids combine the best of both worlds.」（混合網格結合兩種做法嘅優點。— p316）
5. 「Some tricks: you can scale transform your visuals for smaller breakpoints (like tablet), or rearrange it (on mobile).」（小貼士：細斷點（如平板）可以用 scale transform 縮視覺元素，手機就重新排列。— p318）

> 補一句（p317 中文翻譯原意，書冇俾英文原句）：「網格可以歸結為兩個基本數值：外邊距（margin）和欄間距（gutter）。這些數值的一致性才是最重要的。」
